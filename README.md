Java client for the **shield-x** `agent-v1` gateway contract: policy/template pulls, batched event reporting, optional polling/retry/spool, and a Spring Boot starter.

> **Status: private preview (`v0.1.0`).** The artifact is not on Maven Central. Request repository access or build from source; see [Install](#install). The SDK only handles protocol and transport — policy evaluation and template execution remain in the gateway.

- Package root: `com.cdeer.shieldx`
- Maven: `io.github.linyu19872008:shield-x-client-java`
- API guide: [docs/client-java-api-v1.md](docs/client-java-api-v1.md)
- License: [MIT](LICENSE)

## Features

- Pull policies/templates: 304, ETag, revision 0, empty-list clear, failure keeps the old snapshot
- Report events: JSON/NDJSON, gzip, 1000 events / 1 MiB limits, 413 split, 429 backoff, 400 drop
- Optional `Poller`: scheduling, exponential backoff with jitter, template refresh
- Optional `Reporter`: bounded queue, drop-oldest, spool replay, graceful shutdown
- HTTP defaults: no redirects, TLS verification, response-size cap, token redaction
- Spring Boot starter: properties, lifecycle, Health, Micrometer
- Optional `shield-x-template`: reference renderer passing all 14 conformance vectors

## Requirements

- Java 17+ (Java 21 works)
- Maven 3.9+ (the repository ships `mvnw`)
- A shield-x deployment and a site token

## Quick start

```java
ShieldXClient client = ShieldXClient.builder()
    .baseUrl("http://shield-x.internal:8080/shieldx")
    .token("sx_...")
    .gatewayId("gw-prod-01")
    .agentVersion("gateway/2.1.1")
    .capabilities(Capabilities.builder()
        .actions("observe", "block")
        .matchFields("ip", "host", "path")
        .maxRules(5000)
        .build())
    .build();

try (Poller poller = Poller.builder(client)
        .interval(Duration.ofSeconds(5))
        .onSnapshot(store::replace)
        .build();
     Reporter reporter = Reporter.builder(client)
        .state(() -> new ReporterState(store.revision(), store.policyCount()))
        .build()) {

    poller.start();
    reporter.start();
    reporter.enqueue(event);
}
```

`sinceRevision = -1` means “no local snapshot”; `>= 0` sends `If-None-Match: "rev-N"`, and revision 0 is legal. A 304 is not an exception: `PoliciesResult.notModified()` is true.

## Delivery semantics

- at-least-once: retries and spool replay may produce duplicate events; `event_id` is generated by the gateway and must stay stable.
- Queue full drops the oldest event and increments `dropped`; 400 drops the batch; 413 splits; 429/5xx/network back off or spool.
- Sampled sites may report `accepted + rejected < sent`; this is not an SDK data-loss signal.

## Spring Boot starter

```yaml
shield-x:
  enabled: true
  base-url: http://shield-x.internal:8080/shieldx
  token: ${SHIELD_X_TOKEN}
  gateway-id: gw-prod-01
  agent-version: gateway/2.1.1
  poll:
    interval: 5s
  report:
    batch-size: 300
    spool-dir: ./data/spool
```

The starter creates `ShieldXClient` / `Poller` / `Reporter`, starts them via `SmartLifecycle`, and exposes Actuator Health and Micrometer metrics.

## Template rendering

`shield-x-template` is an optional reference implementation:

```java
String html = TemplateRenderer.render(template.content(), vars);
```

It passes the 14 vectors in `template-conformance/cases.json`; a gateway may implement the same rules itself.

## Contract probe

Requires a real shield-x instance:

```bash
SHIELDX_BASE_URL=http://127.0.0.1:8080/shieldx \
SHIELDX_TOKEN=sx_xxx \
SHIELDX_PROBE_EMPTY_TOKEN=sx_empty \
SHIELDX_PROBE_TOKEN_B=sx_other \
./mvnw -pl core -Dtest=ContractProbeTest test
```

CI runs the same probe via `scripts/probe-ci.sh`, which starts MySQL and a real shield-x built from pinned commits.
